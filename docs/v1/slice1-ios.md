# Slice 1 on iOS: entry, More, Preferences and the export metadata policy

Reference: the approved prototype `docs/ui/app/` at revision ff5c5ae. The audit that preceded this work is in [ios-audit.md](ios-audit.md).

## What was built

| Screen / behaviour | Native implementation |
|---|---|
| `launch` | The system launch screen (`UILaunchScreen`) shows the eight-ray mark (64 pt, `--ink`) on `--bg`, in light and dark. It is centred in the area below the status bar, as in the prototype: the launch image is taller than the mark, so the mark sits half the top safe area below the screen centre (31 pt on iPhone, 12 pt on iPad). Generated by `ios/Tools/generate-launch-mark.swift`. No timer holds it. Welcome follows the first frame. |
| `welcome` | `Features/Welcome/WelcomeView.swift`: ⋮ More, mark, "Lightly", tagline, Choose a photo, Camera, privacy line, Privacy Policy link. When the text is too tall for the screen (large Dynamic Type sizes), the content scrolls. |
| `welcome-more`, `more` | `Features/More/MoreSheet.swift`. On phones, a sheet 88% of the screen tall with a grabber: the prototype's `.sheet` asks for 92% and caps it with `max-height: 88%`. On tablets, a centred form sheet 540 pt wide (at most 92% of the width) and 70% of the height. Pages replace each other inside it. Close appears on the first page and Back on every other. |
| `picker`, `picker-cancelled` | `PhotosPicker`, which needs no library permission. Cancelling returns to Welcome unchanged. |
| `camera-permission`, `camera`, `camera-review` | `AVCaptureDevice` permission (the system alert), then the system camera (`UIImagePickerController`), which provides Retake / Use Photo. With no camera (simulator) a plain alert is shown. There is no longer a library-picker fallback. |
| `camera-denied` | `Features/Recovery/RecoveryMessageView.swift`: "Camera access is off", Open Settings, Choose a photo instead. |
| `load-failed` | "This photo can’t be opened": Choose another photo; Try again repeats the same request (an iCloud download can succeed the second time). |
| `preferences` | `PreferencesStore` (typed `UserDefaults`). Appearance System/Light/Dark is applied at once to every window, sheets included. Favourite presets shows "n of 5". Saved signature. Preferred border. **Keep photo metadata** (default on) and **Include location** (default off) are independent. |
| `pref-favourites` | `FavouritePresetsStore`: ordered, five at most, ids from `presets/develop-design-ui.json` (bundled verbatim), shared with slice 2. Drag the handle to reorder. VoiceOver has Move up / Move down actions. Trash removes. |
| `pref-signature` | Structure only. No signature can exist before slice 5, so the page shows "No saved signature", dimmed Draw / Import rows and the approved note (`DEFERRED(slice 5)`). |
| `pref-border` | None/Solid/Photo Frame/Polaroid. None is the default. It is never applied by the save path. |
| `legal`, `privacy`, `terms` | Text comes from `ios/Lightly/Resources/Content/legal.json`, which is **empty** (D2). Until it has text, the page says "This document isn’t available in this build." There are no placeholder bars and no invented text. |
| `about`, `support` | Version and build come from the bundle ("Version 1.0 (1)"). Support: no destination is bundled (D2), so the page says "Support contact details aren’t available in this build." and shows the Version row. When `legal.json` names a `mailto:` or `https:` destination, the approved text and Contact support appear. |
| Export metadata | `ExportMetadataComposer`. Keep photo metadata keeps only aperture, shutter, ISO, date taken, lens, focal length and make/model. Include location keeps the GPS block. Always: sRGB profile, orientation 1, EXIF pixel dimensions rewritten for the new image, no thumbnail, no IPTC. Save copy reads the switches at each save. |
| Orientations | iPhone: portrait only. iPad: all four. |

The appearance tokens (`DesignSystem/Approved/`) are the prototype's. Type uses the prototype's point sizes, scaled by Dynamic Type (body metrics; ×1 at Large), on the prototype's 1.35 line height. Icons are drawn from the prototype's own SVG path data.

DEBUG-only launch arguments for UI tests and captures: `--reset-preferences`, `--seed-favourites` (the five favourites the approved screens show), `--open-unreadable-photo`.

### Differences that remain, and why

1. **Phone More pages (`preferences`, `pref-*`, `legal`, `privacy`, `terms`, `about`, `support`): needs a product decision.** The prototype's screen registry renders these screens as full pages on phones. Its interactive flow, however, opens them inside the More sheet from ⋮ (`welcome-more`, `more`), and they stay in the sheet as the user navigates. The native app follows the interactive flow, so on phones the same page content sits in the sheet, 105 pt from the top instead of 62 pt. On tablets both renderings agree, because the form sheet is used in both. Raised for the user to decide; it is not waived.
2. **System UI.** The photo picker, the camera permission alert (iOS 26 style, with an icon and side-by-side buttons), the Settings app and the camera itself are Apple's. The prototype draws approximations.
3. **Sheet chrome.** The iOS 26 sheet corner radius, the grabber and the dimming of the screen behind the sheet are drawn by the system. The prototype draws a 14 pt radius and 32% black.
4. **Tablet form sheet position.** The system centres the form sheet in the window, so it sits about 9 pt higher than the prototype's. Its width (540 pt) and height (70%) match.
5. **Status bar.** The real system status bar. On iPad it reads "9:41 AM Sat Oct 3"; the prototype reads "9:41 Fri 2 Oct".
6. **Copy that exists only because a dependency is pending (D2):** the legal-unavailable and support-unavailable notes. **Slice 5:** the empty saved-signature state. None of these is in the prototype; they are flagged for approval with the content when it arrives.
7. **`camera` / `camera-review`** cannot be captured on the simulator (it has no camera), and physical devices are excluded. These two screens are system UI.
8. **`more` (editor)** shows the legacy editor behind the sheet until slice 2 replaces it.
9. **The message-screen icon sits at the leading edge** of the text block, as the prototype renders it (a block-level SVG inside a centred grid item). It is matched, but it looks unintended; flagged for confirmation.

## Tests

- Unit (`LightlyTests`): `ExportMetadataPolicyTests` covers all four switch combinations on written JPEG bytes: GPS absent or present, the kept EXIF/TIFF fields, sRGB profile, dimensions, orientation 1, no stale EXIF size, no embedded thumbnail (checked by JPEG markers), no IPTC, no user comment or serial. `LUTEditorViewModelTests.testSaveCopyAppliesTheMetadataSwitchesInAllFourCombinations` runs the same four combinations through Save copy, with the switch changed after the editor opened. Also: `PreferencesStoreTests` (defaults, relaunch persistence, independence, unreadable values), `FavouritePresetsStoreTests`, `BundledContentTests` (catalogue bundled; `legal.json` empty), `ApprovedIconTests`, `AppStateTests` (picker cancel, camera permission paths, load failure and retry, More entries), `WelcomeLayoutTests` (Large, AX3 and AX5), and `SliceOneSnapshotTests`.
- UI (`LightlyUITests`): `WelcomeAndMoreUITests` covers Welcome → Privacy Policy → back to Welcome; every More page and its Back; defaults; the independent switches; persistence across a relaunch (appearance, both switches, preferred border); favourites drag-reorder and remove; and load-failed retry and close. `EditorFlowUITests` covers Welcome, picker cancel, editor ⋮ More, the full editor flow and iPhone staying in portrait.

Totals at the last run: unit 397 passed, 0 failed (iPhone 17, iOS 26.5, Large text). UI 20: 15 passed, 5 skipped (the capture tests skip unless `LIGHTLY_CAPTURE_DIR` is set), 0 failed. `scripts/check_app_icon.sh` passes on the built app.
